## Features

### Trees from distance matrices

Today treescape starts from a Newick string, the standard hand-off from inference tools (IQ-TREE, RAxML, MrBayes, BEAST). But many Python users only have a pairwise distance matrix (from an alignment, k-mers, Mash) or a SciPy `linkage` result, and must glue in another library to get a tree.

```python
TreePlot.from_distances(D, labels, method="nj")   # or "upgma"
TreePlot.from_linkage(Z, labels)                  # scipy.cluster.hierarchy
```

Julia: `TreePlot(D, labels; method=:nj)`.

- **Neighbor-Joining** (Saitou & Nei 1987): clock-free, O(n³). **UPGMA**: average linkage, ultrametric.
- Implement in `treescape-core`, reference first in `treescape-reference`.
- **Independent oracles:** ape `nj()` / `upgma` via phangorn (R, release tier), scikit-bio `nj`, Biopython `DistanceTreeConstructor`, SciPy `linkage(method="average")` for UPGMA topology and heights.
- **Convention to pin first:** tie-breaking when several pairs share the minimum Q / distance (the result depends on it; oracles differ), negative NJ branch lengths (keep, clamp, or redistribute — ape keeps them), rooting of the unrooted NJ tree (midpoint? leave unrooted and root at the last join?).
- Input validation: square, symmetric, zero diagonal, finite, labels unique.

### Smaller items

- **Fan layouts from the API.** `start_angle` / `sweep_total` exist in the core but neither `TreePlot` API exposes them.
- **matplotlib colormaps as `cmap=`.** Callables returning 0–1 float RGBA tuples are currently read as 0–255 ints (near-black). Accept float tuples, or detect matplotlib `Colormap` objects.
- **Python notebook display.** `TreePlot._repr_svg_` (Julia already has `show(::MIME"image/svg+xml")`).

## Performance

- **Sub-quadratic branch styling.** Metadata-driven branch styling is O(nodes × depth) (~0.3 s at 8k tips on a ladder tree). A faster algorithm must preserve the pinned left-to-right Neumaier summation per subtree.
